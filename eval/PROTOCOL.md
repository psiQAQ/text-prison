# TextPrison 实验协议 v0.2

日期：2026-10-24。本文替换 v0.1 协议。Pi 采集、运行记录与人工工作台已实现 v0.2；本轮按四场景探索性配置运行，具体进度见 `runs/<实验>/SUMMARY.md`。方法依据见 [相关研究](../docs/RELATED_WORK.md)，计算口径见 [METRICS.md](METRICS.md)，正式运行前仍须完成 [PREREGISTRATION.md](PREREGISTRATION.md)。

## 1. 与旧协议的实质变化

保留原有 A/B/C/D、语义保护、独立执行者、场景配对和真实 usage。新增或加强：

1. 同时测生成事实支持和必需事实保留；编辑级错误分型，禁止删事实换高分。
2. 对检查反馈的因果归因必须有 C+ 等修订机会对照，而非仅比较 C–D。
3. 用独立行为样本先验证检查器/评委；区分生成质量与评委检出能力。
4. 触发 precision 解释要考虑部署正例基率；unknown 与 not_triggered 分开。
5. 撤销固定百分比与样本量作为默认通过标准；改为带风险依据的预注册。

## 2. 研究问题与证据层次

| 问题 | 主要比较/测量 | 可得结论 |
|---|---|---|
| 完整方案是否有用 | 原生工作流 A–D，语义门禁、目标任务结果、成本 | 该宿主/模型/任务范围的产品效果 |
| 路由规则是否改善输出 | 控制实验 A–C | 提供这些规则的条件效应 |
| 渐进加载是否省资源 | B–C，同源等价规则 | 加载方式及上下文变化的净效果 |
| 具体检查反馈是否有价值 | 反馈消融 D–C+ | 在相同初稿与修订机会下，反馈信息的增量 |
| 能否自动选中正确任务 | 原生触发集、事件日志 | 触发与路由的可靠性，不由输出风格推断 |

主产品对比不自动回答各机制归因问题。风格改善与真实效果分别报告。[R05](../docs/RELATED_WORK.md#r05) [R06](../docs/RELATED_WORK.md#r06)

## 3. 分组与实际提示词

| 组 | 规则/流程 | 约束 |
|---|---|---|
| A baseline | 不安装/注入 TextPrison | 保留同样的事实准确、权限和任务要求，不故意弱化 |
| B static | 全量生成规则，仍保留各 profile 适用条件 | 不同时强制互斥规则；不额外启用修订 |
| C routed | 仅加载适用 profile 和语言的生成规则 | 与 B 同一规则源；不包含检查编排条款 |
| D checked | C + 机械检查 + 至多一次局部修订 | 真实工作流仅在预定条件下修订，报告实际次数 |
| C+ generic-review | 与 C 相同规则，另给普通自查机会 | 用于反馈消融，不把“多一次调用”误认成检查器收益 |

B/C 使用生成专用条款，不能直接注入会命令检查修订的完整 SKILL.md。保存渲染后的提示、规则集合、tokenizer 与哈希。

**反馈消融单独运行：**同一份冻结 C 初稿复制到隔离分支。D 得到机械报告，C+ 得到不含报告的通用复核请求；两者都固定获得一次修订调用，相同模型、来源和调用预算。即使无错误也完成一次复核。该消融不同于生产 D 的按需修订，结果不得混成一个实验组均值。记录实际 Token，最大预算相同不意味着实际消耗相同。

可选外部对照：简短通用“清晰且保留原意”提示，以及固定 commit 的 SimpleEnglish skill-only 配置。仅在共同适用的英文任务上比较；不把 hooks、额外工具或不同权限混入。外部对照不必全交叉所有语言/模型。现有 schema 不支持额外 arm 名称，需先迁移或用独立侧车记录，不伪装成 A/B/C/D。[R02](../docs/RELATED_WORK.md#r02)

## 4. 两条试验轨道，不能混淆

**控制轨道：**固定正确 profile/语言，研究表达规则、加载策略和反馈。强制加载是控制变量，不算自动触发成功。所有组独立会话；共用初稿只用于明确登记的反馈消融。

**原生轨道：**安装真实 Skill，普通任务不点名 Skill，让宿主自然决定是否触发。A 中 Skill 必须真实不可用，不只是提示“不要使用”。记录用户/项目其他 Skills、全局配置、工具和缓存条件。D 没有触发仍保留在 D（按分配组分析）；可附触发者子集，但不能代替产品效果。

宿主版本、模型快照、推理配置和权限固定或完整记录。跨时间调用交错平衡，避免先跑 A 后跑 D 混入服务变化。未支持 seed 的接口不能声称模型随机性可完全复现。

## 5. 任务集、来源与独立验收

首轮主任务覆盖 explanation、procedure、research、agent-spec，中英文分层；reference/structured 先作为契约与误干扰回归，扩展后才能对其宣称主效果。读者与执行者群体按产品实际使用场景定义。

每个任务包应包含：task/scenario ID、用途和语言、来源与哈希、允许转换、必需事实/条件、输出契约、风险标签、时间与调用预算、独立题目或 verifier、环境快照、可见输入与隐藏评分的分界。

隐藏验收只能落实任务已声明的要求，不能加入秘密新需求。标注与 verifier 在候选生成前完成；先用人工参考解验证任务可完成，再用坏例验证失败能够被发现。Skill 不能包含保留集答案、固定输出或特定实例解法。[R06](../docs/RELATED_WORK.md#r06)

同一场景的翻译、改写、模型生成变体和最小变异必须一起分割。开发集可反复迭代；保留集只在规则、评委与统计冻结后读取。不得按试验组收益筛掉“没有提升”的任务，也不得在观察保留集后添加同类规则再称原集是盲测。

旧版 24/96 只是预算示例。实际数量由风险界值、场景差异、读者因素、功效/精度与预算模拟决定。资源不足时只做探索，不降低证据标签。[R24](../docs/RELATED_WORK.md#r24)

## 6. 先校准测量工具，再测产品

开发集建立三份相互关联但目的不同的数据：自然文本误报集、MFT/INV/DIR 行为集、来源支持/必需信息金标集。包含 may→must、条件删除、数值单位错配、因果倒置、引用错配及合法转换。

测量两种能力：生成器是否避免语义损坏；独立评委是否发现人为注入的损坏。后者好不代表前者好。评委不看生成组、模型身份和 linter 分数。

本轮采用两位独立 AI 评委和用户本人这一位人工评委。用户先完成整批独立初判并冻结，再查看 AI 证据并逐项最终裁决；不称为真人双标，不用三票多数决。AI 误报、漏检和分类型分歧主要对照冻结初判，参考 AI 后的裁决另作分析，不能当成完全独立的金标。自由提取声明未经人工对齐，不直接计算声明一致率。正式扩大试验时另行确定双人标注、关键错误全复核和抽样规则。

LLM 评分辅助可以使用，但要固定版本、证据要求和输出格式。比较型评分交换顺序；技术语义主要采用来源逐项核对，不奖励冗长或特定文风。不同模型家族仍可能共享偏差。[R15](../docs/RELATED_WORK.md#r15) [R17](../docs/RELATED_WORK.md#r17) [R23](../docs/RELATED_WORK.md#r23)

## 7. 人类理解试验

每个场景提前设计关键问题及信息定位任务，明确目标读者的语言/领域经验。每位读者不接触同场景多个版本，组别盲化；平衡任务难度、组序和语言经验。样本数量和每人负担由开发集估计，避免固定“每文档六人”被误作统计标准。

主终点为限时关键题全对率；次终点为定位时间、准确率、正确完成封顶耗时与主观费力。没有真实读者时，仅能称机器代理评价。人类数据匿名化，记录必要的背景因素而非无关个人信息。[R13](../docs/RELATED_WORK.md#r13) [R20](../docs/RELATED_WORK.md#r20)

## 8. 下游执行试验

只对可执行的 procedure 和 agent-spec 计算执行成功。将候选文档提供给新的执行 Agent；执行者不加载 TextPrison，不读取写作者来源全文或评测结果，各组基础环境和目标一致。至少覆盖预注册的执行配置，写作者配置×执行者配置分开报告。

任务在临时目录/容器、假凭据、固定依赖和受控网络中运行，每次恢复状态。独立 verifier 检查最终状态，轨迹审计检查权限/关键约束。重复次数用于可靠性，不允许选最好输出，也不能当成新的独立场景。

## 9. 触发、日志与成本

触发测试包括明显正例、明确负例和边界任务，先由人工判定应触发与目标路由。设置已知显式调用与已知无调用样本检验采集器；采集器失败不能解释为宿主触发率为零。

平衡测试集报告 TPR/FPR；另外按代表性任务流估计部署基率，或对多个明确假设的基率作敏感性分析。不从平衡测试集直接发布“真实使用 precision”。自然触发 unknown 独立报告。

按 [METRICS.md](METRICS.md) 保存请求级原始 usage，去重流式/累计/子 Agent 记录。写作、执行、评测分账。API adapter 用真实日志 fixtures 验证；缺失值不补零。冷/暖启动和固定长会话序列另设实验，不混入单轮结果。

## 10. 失败、重跑与排除政策

所有分配试验保留 ID、状态与原因。产物无效、预算耗尽、任务失败或不触发都不能删除。与任务独立的基础设施故障如何处理必须提前写明，所有组采用相同规则，原始失败和重跑均保留。

主要产品结果按预定分母报告；基础设施补跑可附敏感性分析，但不择优替换。只能在不知道组间结果时按预定理由排除确实无效的任务，并记录所有受影响组。实验发现有歧义的任务不悄悄“修到通过”。

## 11. 统计和结论门禁

在每个声明族内预定主比较、主终点、非劣效界值 δ、最小有意义改善、置信水平及多重比较政策。建议将语义/关键约束视为先决门禁，随后评价任务结果，再讨论成本。多语言/多模型/多个主效果的检验若同时用于宣称，应预定 Holm 或固定检验顺序；不能事后选显著的分组。

场景级配对/簇级重采样保留所有重复与翻译的相关性；读者分析使用预先指定的交叉层模型或合适的多向重采样。报告效应量、区间、覆盖率和原始分母。仅两个“宿主+模型”组合时，不能识别宿主本身的效应。

零错误上界、非劣效和缺失敏感性按 METRICS 执行。固定预算用尽后的宽区间结论为“不足以判定”，不是“没有区别”。禁止观察保留集后随意扩样；需要序贯设计时须事前登记停止规则。[R24](../docs/RELATED_WORK.md#r24) [R25](../docs/RELATED_WORK.md#r25)

## 12. 发布材料与最小可接受声明

保存协议版本、分割清单、来源/规则/提示/宿主/模型/检查器哈希或版本、任务初态、所有产物、修订、触发事件、原始 usage、评委判定、执行结果、排除/重跑理由和统计脚本。公开前去除密钥与个人信息。

当前工程实现与具体实测分别留证。只有完成对应证据链后，才能分别说规则违规减少、理解改善、执行改善、按需加载节省或自动触发可靠。任何比例都要带任务范围、配置、分母、区间及缺失覆盖；四场景只给描述统计，不输出无依据的正式置信结论。

## 13. 本轮冻结配置

写作和独立执行使用 Pi `openai-codex/gpt-6-luna` / medium；两位评委为 `deepseek/deepseek-flash` 与 `openai-codex/gpt-6-sol` / high。来源为合成材料，任务包与规则在 `runs/<实验>/inputs/` 冻结。种子 `20261024` 固定分配顺序，不宣称控制服务端随机性。

总上限 128 次 CLI、14400 秒，单次最多 300 秒和 8 个工具回合。分配为冒烟3、校准24、写作16、等修订机会消融8、独立执行8、触发8、候选评审48，另留13次故障预留。失败与重试均计入；未使用的预留不自动扩样。

首轮实际比较为原生 A/D、受控 B/C，以及单列的 C+/D 反馈消融。B/C 从同一规则源提取生成条款；A/D 文件权限一致，A 无 TextPrison，D 通过原生目录元数据隐式发现并可调用固定检查器。显式读取的冒烟只检验采集器，不计入隐式触发成功率。触发意图标签来自合成设计，须人工确认后才可推广到真实任务流。
