# TextPrison v0.2 文档设计：有证据的表达约束

日期：2026-10-24。**本次仅更新文档，运行时实现仍为 v0.1。** 新指标、评测 runner、规则编译器和宿主适配器尚未实现。来源与证据边界见 [RELATED_WORK.md](RELATED_WORK.md)，未来修改路径见 [IMPLEMENTATION_DELTA.md](IMPLEMENTATION_DELTA.md)。

## 1. 目标与成功含义

TextPrison 是按输出用途选择表达规则的 Skill，不是完整 ASD-STE100 认证器。项目需分别证明：内容含义保持、读者理解改善、执行任务更可靠、成本可接受。更少违规、更短句子或更小 Skill 文件均不能替代这些结果。

设计从三套规范提取原创规则，但每条规则必须区分：规范来源、机器可检查范围、实证支持和待验证假设。Google/Microsoft/STE 提供写法参考，不提供本项目成功率或节省率门槛。[R08–R10](RELATED_WORK.md#r08)

## 2. 保留六类路由，新增风险与内容角色

| Profile | 主要对象 | 应保护的内容 | 风格范围 |
|---|---|---|---|
| explanation | 问答、概念说明 | 定义、机制、假设和边界 | 回答问题优先；不强制极短句或固定标题 |
| procedure | 安装、部署、故障排查 | 前提、动作对象、顺序、停止条件 | 已知条件先于动作；不新增策略 |
| reference | API、参数、配置 | 类型、默认值、范围、单位、版本 | 条目统一；不改标识符和术语差异 |
| research | 文献、实验、推导 | 模态、否定、误差、适用条件、引用 | 精确优先；无全局句长或模态词禁令 |
| agent-spec | AGENTS.md、Skill、任务约束 | 目标、权限、作用域、成功/停止条件 | 降低指代歧义；不暗增授权 |
| structured | JSON 等机器输出 | 精确格式与 schema | 不套自然语言排版；当前仅实现 JSON |

混合 Markdown 应按段落角色适用规则：正文、步骤、表格、代码、引用、公式、机器字段分别处理。现有检查器仍一次接受一种 profile；自动分段是后续能力，不能通过文档更新宣称已实现。

风险是审核标签，不是另一个写作风格。例如带破坏性命令的 procedure 要加强语义验收，不是自动增加来源未要求的警告。中文不用英文词数或词典作硬约束。[R04](RELATED_WORK.md#r04)

## 3. 三种契约，不用一个总分代替

**内容契约：**来源、任务要求、必需事实、允许转换、关键语义关系。必须保持主体、对象、条件、否定、可能/必然、数值及单位归属、版本、因果与引用对应。原子事实保留率是任务要求覆盖，不要求把来源所有背景都复制进摘要。

**输出契约：**JSON Schema、必须/禁止的精确文本、指定字段与章节。只有明确约定或语义安全必要的条件才能成为硬门禁。纯粹文风偏好默认 warning。

**测量契约：**在生成前固定检查对象、分母、真值来源、失效模式、缺失值和发布结论范围。适用规则不能由候选输出临时决定，否则可通过删除内容逃避检查。

事实支持率参考 FActScore；必需事实保留率与关键关系核对是针对其只测 precision 的补充设计。编辑级定位参考 SALSA。二者都不是对中文技术文档的现成质量保证。[R14](RELATED_WORK.md#r14) [R15](RELATED_WORK.md#r15)

## 4. 规则注册表的目标格式

以下为下一版字段需求，不是现有 rules.json 已支持的字段。

| 字段组 | 内容 |
|---|---|
| 身份 | rule_id、版本、owner、变更理由 |
| 证据 | source_id、来源位置、来源版本/哈希、normative/empirical/project_hypothesis |
| 适用性 | profile、语言、内容角色、前提、例外、排除区 |
| 强度 | contract/hard 或 style/advisory；风险依据 |
| 检查 | exact/heuristic/semantic/human；输入要求、实现入口、覆盖限制 |
| 回归 | 阳性、阴性、边界、最小变异、误报例；fixture 的 scenario_id |
| 编译 | 面向模型的短指令、面向检查器的配置；两者同源但验证独立 |

不自动把 Google 与 Microsoft 风格包的同类规则相加。合并前建立规则对应表、冲突优先级和领域词表。Vale 仅作为可选风格诊断后端；保留自有 JSON/契约检查与语义验收。[R04](RELATED_WORK.md#r04)

## 5. 运行时与实验室分开

运行时：识别用途 → 只加载相关规则 → 按契约直接生成 → 对落盘产物做机械检查 → 在有足够来源时审查关键语义 → 最多一次局部修订。失败后如仍不能满足约定，报告限制，不循环重写到“分数好看”。

实验室：独立来源清单 → 冻结评测题与 verifier → 随机成对生成 → 独立事实/人工/执行评估 → 统计与成本账本。参考文献、全部评测规则、原始审计 JSON 不默认进入生产上下文。

完整语义评委不是低成本运行模式的强制额外模型调用。离线评测成本单列；若生产模式主动启用模型语义审查，其调用必须计入生产成本，不能移到评测账本隐藏开销。

## 6. 不变性和最小变异测试

参考 CheckList 的 MFT、INV、DIR，建立两类独立测试：生成器应保持含义；评委应发现被注入的错误。[R17](RELATED_WORK.md#r17)

| 类别 | 测试 | 预期 |
|---|---|---|
| 最小功能 | 一个条件句、一项单位换算、一条 API 默认值 | 保护全部必需含义；合法转换按契约接受 |
| 不变性 | 调整空白、Markdown 包装、无语义影响的换行 | 事实/硬约束结论保持；代码与原样引文不被改写 |
| 方向性 | may→must、≤→≥、删除适用条件、交换主体、错配引用 | 语义错误应被标记；不能因句子变短而获益 |
| 误干扰 | 代码修复、严格原样返回、数学公式、用户指定文体 | 不引入无关风格干预 |

不要求改写文本逐字一致。压力样本与真实分布样本分开报告，不能把变异检测率当作真实错误率。

## 7. 自动触发和低 Token 的真实边界

保留单一 Skill 源和两种项目级安装布局；不新增全局 hooks、权限或 MCP。宿主的 description 匹配只是调用机制，不是强制拦截。显式调用、自然触发、严格机器输出是不同测试条件。[R26](RELATED_WORK.md#r26) [R27](RELATED_WORK.md#r27) [R28](RELATED_WORK.md#r28)

保留渐进加载：元数据 → 主 Skill → 对应 profile/语言。原始 120/600/300/200 Token 数值仅是历史预算草案，撤销为默认门槛；新预算按目标 tokenizer、可接受任务成本和真实会话账单在预注册中填写。不得据此删掉关键语义规则。

测量静态规则长度、任务累计输入/输出、缓存、修订、工具与子 Agent、长会话残留。冷启动与暖会话分开；仅比较同一模型配置内的干预变化。按需加载需要对比等价全量规则，而非任意缩短提示词。[R21](RELATED_WORK.md#r21) [R29](RELATED_WORK.md#r29) [R30](RELATED_WORK.md#r30)

## 8. 效果判断与模式选择

优先级为：内容/权限安全 → 目标任务结果 → 成本和延迟 → 风格诊断。不得用其他指标的高分抵消关键语义错误，不发布未经验证的综合“质量分”。

若 C（路由无修订）在任务结果非劣且成本更低，可作为经济模式候选；若 D（带检查修订）提高任务结果但更贵，可作为质量模式候选。当前二者都只是试验条件，不是已验证产品档位。完整指标见 [METRICS.md](../eval/METRICS.md)。

## 9. 阶段验收，不承诺日历工期

| 阶段 | 要得到的证据 | 不能跳过的条件 |
|---|---|---|
| P0：测量基础 | 内容契约、最小变异、schema 迁移设计、usage 与触发日志 fixtures | 已知阳性/阴性可识别；原型能力与规划分开 |
| P1：开发集校准 | 误报分析、评委标注、基线差异、预算和样本量模拟 | 开发集不再充当最终验证集 |
| P2：预注册冻结 | 主要终点、界值依据、抽样、失败政策、样本量和版本哈希 | 所有关键 UNSET 字段填完，保留集未查看 |
| P3：盲测与发布 | 全部轨迹、独立验收、置信区间、成本与适用范围 | 未触发/超时不消失；无证据则标记结论不足 |

本次没有修改运行时代码、Skill 正文或 rules.json。原型的 mechanical passed、semantic not_evaluated、STE not_evaluated 区分必须保留。
