## 4. P0＋P1 的采纳结果

### P0：允许必要展开，保留清楚的原文

主 Skill 只增加简短清晰度原则；详细方法集中在现有 STE-inspired 参考，处理有歧义的名词串、已有关系、插入信息、必要名词重复及正常技术搭配。固定术语、未知执行者、被动表达、模态、否定、条件和权限不因文风改变。

新增示例包括缓存用途已经明确时展开名词串、保留配置校验条件、缺少上下文时不补因果，以及保留正常技术表达和“不显著”结论。语言参考只增加中文修饰链与英文关系标记的差异；解释和科研参考补交付形式及限定保护，不重复整套通用方法。

### P1：明确请求的技术回答直接在聊天中交付

主 Skill 的发现描述、正文、展示说明、参考索引和用户文档一致纳入明确要求使用 TextPrison 的技术回答，沿用 explanation、research 等五类用途。聊天正文只是交付形式，不增加第六种用途或全局 hook。

保留 `allow_implicit_invocation: true` 和文档任务的自动发现；普通聊天及未指定使用 TextPrison 的技术问答不进入此流程。技术回答默认只使用文字指导，不为检查创建文件；未请求诊断、未使用工具时不附机械状态清单，已请求或选用的检查未能运行时仍报告原因。

README 仅同步范围、示意调用、导航和目录，保留安装主线及历史 CLI 案例。使用说明、设计说明和来源说明同步更新；安装器、Vale/AutoCorrect 配置及版本不变。Skill 内的相对引用保持自包含，不加载研究目录或本地论文。
