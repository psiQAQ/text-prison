# 指标定义与有效性边界

版本：文档协议 0.2，2026-10-24。以下是待实现、待校准的测量契约，不是原型已输出的指标。来源编号对应 [研究目录](../docs/RELATED_WORK.md)。本项目不采用单一加权总分。

## 1. 单位、分母与缺失

**场景 scenario** 是主要独立抽样单位。同一来源的中英译本、改写、不同模型输出和重复运行共用 scenario_id。task 是具体条件；run 是一次试验；artifact 是可评估产物。增加模型调用次数不增加独立场景数。

对同一场景的重复先求均值，再按预先固定的场景/层权重汇总。不得让重复次数多、句子多或原子事实多的文档自动获得更高统计权重。另报微平均供诊断，不替代主要宏平均。

所有结果都有三部分：值、分母、coverage。没有评估用 null/not_evaluated，不填 0；不可评估事实与已证实不受支持事实分开。分母为零的比率记 undefined。运行失败与测量缺失也是结果，不能因日志不完整而默认为成功。

## 2. 语义：同时约束“说错”和“漏说”

### 2.1 生成事实支持率（FSP）

将候选文本的可核查事实去重为原子命题。每个命题连同其条件、否定、模态、数值单位和版本一起判定，而不是只匹配数字。标签为 supported、contradicted、unsupported、unassessable。

设总命题数 N，得到支持的为 S，不可判定的为 Q：

\[
FSP_{verified}=S/N,\qquad FSP_{possible}=(S+Q)/N.
\]

区间是未判定事实的可行范围，不是统计置信区间。另报已确定判定覆盖率 (N−Q)/N、矛盾数量与无来源新增数量。unsupported 表示在约定来源范围内无支持，不自动等于现实中为假。N=0 不给满分，还要检查任务是否被拒答或遗漏。

这借鉴 FActScore 的原子事实支持思想，但不是使用其现成模型获得的原版分数。[R14](../docs/RELATED_WORK.md#r14)

### 2.2 必需事实保留率（RFR）

生成前由任务与来源定义必需事实集合 R。允许摘要删除的背景不在 R 中；关键条件应与对应事实绑定。候选中被完整保留且有来源支持的事实数为 K：

\[
RFR=K/|R|.
\]

部分保留但丢了必要条件不算通过；未知项另报范围与覆盖率。禁止看完候选文本才缩小 R。该指标是 TextPrison 的补充设计：只测 FSP 会奖励“少说少错”。[R14](../docs/RELATED_WORK.md#r14)

### 2.3 关键语义错误与编辑审查

编辑审查定位 source span、candidate span、错误类型、严重度及证据。参考 SALSA 的编辑级思路，但使用本项目技术任务分类。[R15](../docs/RELATED_WORK.md#r15)

| 严重度 | 判定规则 | 例子 |
|---|---|---|
| critical | 改变权限、必要条件、安全边界、主要科学结论或关键执行行为 | “可能”变“必然”、关闭校验、将上限改成下限 |
| major | 改变重要事实或遗漏必需信息，但未达到预定义关键风险 | API 默认值错误、必要输入缺失 |
| minor | 不改变关键行为的局部准确性/指代问题 | 可定位但不影响决策的非关键标签问题 |
| style_only | 无语义影响的偏好问题 | 非必要的排版或句长建议 |

具体例子需由领域人员在开发集校准。不要以数量加权把 critical 抵消为“总体高分”。主报含至少一个 critical 的产物比例、RFR 和 FSP；另报各错误类型。任何已确认 critical 必须阻断该产物的“安全通过”声明。

评审不全时报告全体产物中的已确认错误下界和潜在错误上界；不能只在完成评审的子集中计算后宣称覆盖全体。若随机抽样审查，明确抽样总体和权重。

## 3. 人类理解：限时完成且答对

生成前从来源定义关键理解题及答案，提前固定每场景时限 T_i。一次读者—文档观察的主终点：

\[
H_{ir}=\mathbf{1}\{\text{在 }T_i\text{ 内全部关键题正确}\}.
\]

先对每场景读者求均值，再按固定权重汇总。辅助指标为各题准确率、第一次定位正确信息时间、完成时间与主观费力程度。失败、错误或超时观察的“正确完成所需封顶时间”记 T_i；成功观察记实际完成时间。只有成功者的平均耗时可单列，但存在选择偏差，不能独立证明效率提高。

耗时比较应考虑 T_i 不同，可报告预注册的标准化时间 t_i/T_i；时限按任务校准，不按组设置。隐藏组别、模型名、写作规则；同一读者不阅读同一场景的多个版本。

这是对受控语言阅读实验及使用效果框架的适配，不是 ISO 规定的唯一计算方法。SARI/LENS/英文阅读公式仅在匹配语言、任务和参考条件时作为辅助；不替代读者实验。[R11–R13](../docs/RELATED_WORK.md#r11) [R18–R20](../docs/RELATED_WORK.md#r18)

## 4. 下游 Agent：独立验收的成功率

一次独立执行成功必须同时满足：在预算内完成全部已公开要求、独立 verifier 通过、未违反预定权限和关键约束。执行者只读候选文档和各组相同的基础环境，不读写作者评测报告，不加载 TextPrison。

对场景 i、组 a、重复 r 定义 y_iar∈{0,1}：

\[
p_a=\frac{1}{M}\sum_{i=1}^{M}\frac{1}{R_i}\sum_r y_{iar},\qquad
\Delta_{D,A}=p_D-p_A.
\]

上式为场景等权示例；若分层权重不同须预注册。报告百分点差及场景配对区间，不仅报告相对百分比。部分测试通过率是诊断，不是完整成功。

固定预算内的失败、超时和越界保留为失败。全平台故障等与任务无关的事件可以按预注册政策补跑，但原记录保留，不能只给实验组重跑，不能从多次轨迹里选最好的一次。[R06](../docs/RELATED_WORK.md#r06) [R22](../docs/RELATED_WORK.md#r22)

可选稳定性指标 pass^k：同一场景预先指定的 k 次独立重置运行全部成功的比例。它不是“k 次至少一次成功”的 pass@k，也不要直接将总体平均 p 的 k 次方当作观测值。重复可靠性与单次成功率分别报告。

## 5. 规则遵循与检查器本身的质量

参考 IFEval 的两种层级，但只使用对本任务有实际意义、预先声明的硬约束。[R16](../docs/RELATED_WORK.md#r16)

| 指标 | 定义 | 注意事项 |
|---|---|---|
| 单项硬约束通过率 | 已验证通过的硬约束数 / 全部适用硬约束数 | 同时报未完成检查比例；未知不能算通过 |
| 完整契约通过率 | 全部适用硬约束均完成且通过的文档数 / 全部应检文档数 | 是验收完成率，不等于语义正确率；无适用约束不计入 |
| 检查器 precision | 复核为真实问题的告警 / 全部被复核告警 | 应对告警随机抽样或全量复核，不能挑明显错例 |
| 检查器 recall | 被检测的问题 / 独立金标问题 | 必须检查未告警文本；仅复核告警无法估计 recall |
| advisory 密度 | 风格警告 / 自然语言长度 | 英文每千词、中文每千汉字分别报告，不跨语言直接混排 |

真实文本误报、最小变异检测率与无关任务干扰分开。句长、Flesch 类分数、词汇替换数量只用于诊断，不能担任本项目的主要有效性指标。

## 6. 自动触发：增加真实基率与可观测性

按独立人工意图标签计算 TP、FP、FN、TN：

\[
TPR=TP/(TP+FN),\quad FPR=FP/(FP+TN),\quad Precision=TP/(TP+FP).
\]

平衡的正负例测试集适合估计 TPR/FPR，但其 Precision 不能直接外推到低触发率工作流。部署中应触发任务比例为 π 时，在类条件表现可迁移的假设下：

\[
PPV(\pi)=\frac{\pi TPR}{\pi TPR+(1-\pi)FPR}.
\]

**仅作算术示例，不是实测：**固定 TPR=90%、FPR=5%，改变任务基率即可显著改变 Precision：

| 应触发任务比例 π | 推算 Precision | 含义 |
|---|---:|---|
| 50% | 约 94.7% | 人为平衡的正负例测试集 |
| 5% | 约 48.6% | 应触发任务较少的使用场景 |

因此原来的“Precision≥95%”不能脱离任务基率使用。

有调用事件或明确 Skill 文件读取证据才记 triggered。无事件但日志覆盖完整，可记 not_triggered；日志不完整记 unknown。报告可观测覆盖率；未知样本做最好/最坏分配的敏感性分析，不能当作阴性。

路由单独报：成功触发后的 profile/语言准确率，以及所有应触发任务中正确触发并路由的端到端比例。混合文档采用预标注的必需 profile 集合；主要口径是集合完全匹配，额外加载成本另报。原型还没有自动分段采集。

## 7. Token、费用与延迟

### 7.1 三本账

| 账本 | 计入 | 用途 |
|---|---|---|
| production_writer | 生成、规则读入、工具往返、生产检查/修订、可见子 Agent | 实际写作模式开销 |
| downstream_executor | 阅读文档后的执行、失败与重试 | 写作+使用的全链路价值 |
| evaluation_only | 盲评、独立 verifier 编排、人工与评分模型 | 实验支出，不冒充生产开销 |

如果产品确实调用语义评委，它属于 production_writer，而不是 evaluation_only。共用初稿的反馈消融要分别记录实际共享实验支出和“每条候选工作流包含一次初稿”的可比成本，禁止混用。

### 7.2 Provider 计量

每个请求保留 provider、SDK/CLI 版本、request/message ID、原始 usage、是否累计、是否包含子 Agent。流式重复事件去重；累计对象取正确的差值或终值，不逐条相加。

OpenAI 的 cached input 通常是输入总量的子集，reasoning output 是输出总量的子集，不二次累加。缓存写入等计价类别随接口版本核验；总 Token 分类与美元账单分类分开。Anthropic Messages 的普通输入、缓存创建和读取是不同输入类别；CLI/SDK 聚合后的语义须重新验证。[R29](../docs/RELATED_WORK.md#r29) [R30](../docs/RELATED_WORK.md#r30)

总消耗用实际所有调用的规范化输入+输出；不要另外加静态 Skill Token 造成重复计算。静态大小用于诊断。跨模型 tokenizer 不同，因此主要比较同配置内组间差异。价格取实验时快照；订阅额度不能冒称 API 实付美元。

### 7.3 主要成本量

\[
Saving_{C,B}=1-T_C/T_B,
\qquad
CPS_a=\frac{\sum_{\text{全部尝试}} cost}{\sum_{\text{全部尝试}} success}.
\]

CPS 包含失败成本；成功数为零记 undefined，不填 0。Token per success 同理。上式适用于平衡试验/明确的任务混合；不平衡设计按预注册场景权重计算对应期望成本与成功概率之比。

给出成对成本差、成本比及区间；usage 缺失时只报已观测下界和覆盖率，不能宣称确切节省。冷启动、暖会话与固定长会话序列分别报告。

端到端时间、首次可用结果时间、p50/p95、修订次数分开。p95 样本少时不稳定，必须附样本数和不确定性，不以几个样本给出精确尾延迟承诺。[R21](../docs/RELATED_WORK.md#r21)

## 8. 推断、非劣效与零错误

主比较以 scenario 配对。重复生成、执行模型和同源翻译保留在场景簇中；读者数据还存在 reader 与 scenario 交叉因素。使用预注册的簇级重采样或合适的分层模型，不能对所有句子/事实/运行当独立样本求极小 p 值。

非劣效示例：预定最大可接受损失为 δ>0，若 Δ=D−A 的区间下限高于 −δ，才支持所声明的非劣效。δ 来自任务风险与实际可接受损失，而不是看完数据才选择。“未显著变差”不等于“已证明不劣”。[R24](../docs/RELATED_WORK.md#r24)

零事件示例：若 n 个独立同分布、来自目标总体的单位中均未见错误，在单侧 95% 精确二项模型下，错误率上界为：

\[
p_U=1-0.05^{1/n}.
\]

| 独立单位数 n | 零事件时的单侧 95% 错误率上界 | 解读 |
|---|---:|---|
| 96 | 约 3.07% | 不能据此声称真实错误率低于 1% |
| 299 | 约 0.997% | 在上述假设下刚满足上界低于 1% |

这是模型假设下的算术，不是对现有数据的结论。相关重复不能充当新的独立单位；人为压力集不具总体代表性；全零数据的普通 bootstrap 不能提供有效的零风险保证。[R25](../docs/RELATED_WORK.md#r25)

## 9. 允许发布什么结论

| 证据 | 允许的说法 | 不允许的说法 |
|---|---|---|
| 只运行 linter | 指定规则的违规减少 | 阅读理解、成功率、事实性已改善 |
| 只有 LLM 评分 | 某评分模型在指定协议下更偏好 | 人类理解得到验证 |
| 控制实验强制加载 | 指定规则干预的条件效应 | 自动触发可靠 |
| 真实读者+独立执行+完整 usage | 在明确任务/配置范围内的效果与取舍 | 所有语言、模型、文档通用有效 |
| 区间过宽或关键字段缺失 | 证据不足，需要限定结论 | 没有显著差异所以等效 |

所有默认数值阈值均由 [预注册](PREREGISTRATION.md) 决定；这里提供计算逻辑，不暗含已验证门槛。
