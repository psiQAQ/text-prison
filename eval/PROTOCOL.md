# TextPrison A/B 与消融实验预注册草案

状态：方案，尚未运行。日期：2026-10-24。样本量、预算和门槛是初始建议，应在开发集校准后、读取保留集结果之前冻结。调整须新建协议版本，不能回写历史方案。

## 1. 需要回答的问题

H1：在不降低正确性的情况下，输出类型专用规则能否让人更快、更准确地完成阅读任务？
H2：读取该文档的独立 Agent 能否更可靠地完成原本规定的任务？
H3：按需加载是否比等价的全量规则更省总 Token？
H4：加入机械反馈后的真实质量收益是否足以抵偿修订成本？
H5：实际安装后能否在该触发时触发、不该触发时不干扰？

不能把违规率下降直接称为可读性或任务成功率提升。不能把 Skill 文件变小直接称为总 Token 降低。

## 2. 实验组

所有组具有相同的任务、来源事实、原始可见要求、工具权限和输出契约。准确性/安全性底线对所有组相同。A 没有风格 Skill，但不故意弱化任务说明。

| 组 | 干预 | 目的 |
|---|---|---|
| A baseline | 无新增风格规则 | 现有工作流基线 |
| B static | 全量规则文件一次加载；保留各 profile 条件，不同时强制所有规则 | 全量提示基线 |
| C routed | 同一规则源，只加载适用 profile/语言；无反馈重写 | 衡量路由/精简上下文效果 |
| D checked | C + 机械检查反馈 + 至多一次局部修订 | 完整候选产品 |

A–D 为主要产品对比；A–C 判断规则本身；B–C 判断按需加载；C–D 判断检查修订的净价值。D 的修订会增加计算，C–D 不能单独归因于“检查器信息”。要进一步归因，增加预注册的 C+ 组：相同额外修订预算，只有普通自查提示，没有检查器反馈。C+ 是扩展实验，不默认混入本轮四组。

控制实验必须把生成规则与检查编排分开：B/C 使用相同的语义底线与生成条款；B 提供带适用条件的全部 profile，C 只提供当前 profile。两组均不注入 SKILL.md 中要求执行检查和修订的编排步骤。D 才启用这些步骤。保存各组实际渲染提示的哈希，避免名义上是 C、实际执行了 D。正式宿主试验则使用真实完整 Skill。

第一轮控制实验由测试框架提供预定 profile 和规则文件，避免触发波动污染规则效应。第二轮在实际 Codex/Claude Code 中自然触发；必须单独报告，不能把强制注入结果当成自动触发效果。

## 3. 数据集与冻结

开发集 24 个独立任务：4 类输出 × 2 种语言 × 每格 3 个。
保留集建议 96 个独立任务：4 类输出 × 2 种语言 × 每格 12 个。
四类为 explanation、procedure、research、agent-spec；reference/structured 在首轮做回归与误干扰测试，下一轮再扩展主要结论。

每个任务包含：task_id、scenario_id、来源及哈希、读者背景、语言、profile、输入仓库快照、原始目标、原子事实清单、关键不可改变条件、允许操作、成功判定、时间/调用预算。作者使用的资料和隐藏验收规则分离；隐藏判定只能落实已知要求，不能设置来源未提供的秘密要求。

所有来自同一事实场景的翻译、改写、难度变体必须共用 scenario_id，整组进入同一数据划分。若 96 份文本实际是 48 个场景的中英译本，统计上的独立场景只有 48 个，不能当作 96 个。

冻结后保存：协议版本、任务集哈希、规则/Skill/检查器提交、宿主与模型版本、依赖锁、工具 schema、权限、随机顺序种子。来源引用无需每次联网，避免来源变化与工具延迟混入风格效应。

24 和 96 是实施起点，不是功效保证。开发集先估计成对差异、基线成功率、场景内相关性和读者差异，再对主终点/非劣效界限做样本量模拟。必要时在盲测前扩样。

## 4. 写作试验数量与控制变量

开发试验：24 × 4 组 × 2 个固定“宿主+模型”配置 × 1 次 = 192 次写作试验。
完整候选盲测：96 × 4 组 × 2 配置 × 3 次 = 2304 次写作试验。D 组最多额外 576 次修订；一次宿主试验可能包含多次底层模型调用，二者不是同一个计数。

按 task/config/repeat 成对比较，组顺序随机且随时间平衡。每份文档来自独立新会话/工作目录，不让模型看到其他组的回答。使用受支持的模型参数；服务不支持 seed 时，只固定调度种子，不能声称复现了模型随机性。

同一配置内固定模型快照或记录实际模型 ID、reasoning effort、工具、上下文、权限和预算。若服务端模型只能使用可变别名，应在短窗口完成、交错各组并记录日期，不能承诺字节级重现。

每个宿主/模型单独报告处理效应。只有两种“宿主+模型”配置时，宿主与模型是混杂的；不能从结果得出某一个宿主本身更好。要研究宿主效应须增加跨宿主同模型或更完整设计。

## 5. 人类阅读实验：量化理解，不是仅给文风打分

从保留集预先选 24 个任务，覆盖语言、文档类型和难度。每个任务取预先指定的一个写作配置和重复，四组各一份，不能看结果后挑“最好的一篇”。每份产物获得 6 个独立读者判定，共 24 × 4 × 6 = 576 次读者—文档观察。

一种分配方式是 48 名满足目标语言/领域要求的读者，每人 12 份、来自不同场景的文档。使用平衡随机分配；同一读者不能读同一个场景的多个组版本，防止学习迁移。两种语言的读者能力与领域经验须记录并平衡。

在生成前，根据来源定义理解题：关键参数、前置条件、不能执行的动作、结论适用范围等。每份约 3 个问题并标明关键题，答案标准由独立人员确定。去掉模型名、组名、提示词和作者身份。

主终点：在预先规定的时间预算内正确回答所有关键题的比例。辅终点：准确率、回答时间、首次找到指定信息的时间、信心与主观易读性。时间与正确性联合报告：不能把答错但很快当作改善；报告含失败/超时的封顶耗时，成功者条件耗时只作次要指标。

没有真实读者时只能报告机器代理指标，不能把 LLM 评委的“易读性分数”改名为人类阅读收益。盲评和问卷数据按隐私要求脱敏，不收集无关个人信息。

## 6. 下游 Agent 实验：写作者与执行者分离

流程：固定来源与任务 → 各组生成文档 → 新的执行 Agent 只读取该文档及相同基础环境 → 隐藏测试/安全轨迹审计判定结果。

执行者不加载 TextPrison，不知道组别，不看原始完整来源、写作者审计或其他版本。它可以获得各组相同的任务目标，但不能获得重复了所有关键步骤的额外提示，否则文档质量影响会被掩盖。使用至少两个执行配置，并保留“写作者配置 × 执行者配置”分组结果。

只对确实可执行的 procedure 和 agent-spec 任务计算执行成功率；不能把概念说明或科研文本强行转成 shell 任务。按上述矩阵，可执行任务若为 48 个，则 48 × 4 组 × 2 写作者配置 × 3 次 × 2 执行配置 = 2304 次执行试验，额外计费，必须单独预算。

主终点是固定预算下首次尝试的完整成功：全部已知验收要求通过，且没有越界动作。次终点为关键约束违反率、工具调用数、修复次数、耗时、Token 和部分完成率。超时、工具失败、未完成都不能从分母悄悄移除。

执行环境使用临时目录/容器、假凭据、模拟文件和固定依赖；不得接入生产系统。每次恢复初始状态。真实敏感配置、网络访问和破坏性命令不作为默认测试资源。

## 7. 自动触发与误干扰：单独测

正例包括自然措辞的文档编写/审查任务；负例包括代码修复、数学求值、逐字引用、创作、严格 JSON 返回、已有风格明确的短任务等。是否应触发由任务意图标注，不仅凭关键词：严格 JSON 若明确要求 schema 约束可作为正例，普通代码返回不因此自动成为正例。

建议先建立 40 个正例、40 个负例，覆盖明显与边界案例。两种宿主各 3 次，合计 480 次触发试验。不要在提示中提到 Skill 名。

记录证据：宿主 Skill 调用事件、明确的 SKILL.md 文件读取记录、实际 profile/语言选择。仅看到正文“像被优化了”不是触发证据；不可观测时标记 unknown，单独报告观测覆盖率。

度量：precision、recall、误触发率、路由准确率、首次/重复调用次数、未触发和误触发的成本。端到端 A–D 采用意向处理分析：分配到启用 Skill 但未触发的试验仍留在 D，不能剔除后再声称产品可靠。

明确范围限制：此起步包仅提供 Skill 配置，没有实现原生事件采集或通用最终回复拦截器。两种适配器必须在固定宿主版本上验证。

## 8. 多维指标与 Token 口径

| 维度 | 原始指标 | 判定来源 |
|---|---|---|
| 语义 | 必需事实保留率、无来源新增、条件/否定/模态改变 | 盲审、来源映射、任务验收 |
| 人理解 | 正确率、限定时间内成功率、检索/回答时间 | 真实读者 |
| Agent | 首次完整成功率、越权/约束违反率 | 隐藏测试、动作轨迹 |
| 规则 | 按 rule_id 的错误/警告密度、误报率 | 检查器与人工复核 |
| 触发 | precision、recall、误触发、路由准确性 | 宿主实际事件 |
| 开销 | 累计输入/输出、缓存、修订、总费用估算 | 原始 usage 与版本化适配器 |
| 速度 | 端到端 p50/p95、首次结果时间、修订次数 | 单调时钟与事件 |
| 干扰 | 无关任务质量变化、原样内容被改动 | 负例回归 |

英文风格违规密度可按每 1000 个自然语言词，中文按每 1000 个汉字报告；不混合两种分母，不把 Flesch 等英文分数直接套在中文上。数字长度、总词数、句长只是辅助指标。

Token 不是“最终答案词数”。每个试验包含所有模型步骤、规则加载、工具往返、反馈、修订和可见的子 Agent 开销。记录规范化总输入、输出及其分项；评测专用评委成本单独记为 evaluation，不伪装成产品生产开销。下游执行成本单独报告，也可另报写作+使用的全链路成本。

OpenAI usage 的 cached input 属于 input，reasoning 属于 output，不能重复相加。Anthropic Messages usage 的 input_tokens、cache_creation_input_tokens、cache_read_input_tokens 是分开统计的输入类别。CLI 包装层可能有不同聚合语义；不要拿 API 字段规则未经验证直接套 SDK 累计对象。

适配器应保存原始日志和 provider/schema 版本，用真实样本测试：同一消息的多个流事件去重；会话累计值取末值或差值，而不是逐条累加；主 Agent 与子 Agent 是否已汇总必须核实。缺失用 null，并报告覆盖率。不要索取或存储模型隐藏推理正文，只需要 usage、动作和产物证据。

跨模型 tokenizer 不同，不直接用原始 token 数比较模型的效率排名；主要比较同一宿主/模型内的组间变化。费用使用运行时价格快照/CLI估算并注明依据；订阅额度不等于 API 美元成本。

成本指标：整个组所有尝试的总成本 / 成功试验数，分母为 0 时为不可定义，不填 0。它不是只在成功样本中计算平均成本；失败成本必须计入。

冷启动、新会话与暖会话分开报告。服务端缓存不可控时记录实际缓存命中，而不宣称强制关闭。长会话附加测试采用预先固定的任务序列，记录规则残留成本和上下文压缩。

## 9. 统计与防止自证

以 task/scenario 为成对单位，保留重复生成和多个执行者的组内相关性。按语言、profile、宿主分层；成对簇 bootstrap 或合适的混合效应模型，报告效应量与 95% 区间。人工数据还需考虑 reader 与 task 两个交叉因素。2304 次写作不是 2304 个独立场景。

在运行前指定主比较 A–D、主要终点、非劣效边界和多重比较处理。其他对比为机制分析/探索，不择优发布。不要一边查看 holdout 一边增加规则，再用同一 holdout 宣布提升。

语义审查者不看风格组标签与规则清单。LLM 评委只能辅助，随机交换顺序、保留来源证据、允许 uncertain，并由人工复核关键错误和抽样误报。不同模型家族有助于减少同源偏差，但不是独立性的保证。不能用与训练/调参完全相同的检查器总分充当唯一外部终点。

## 10. 候选验收门槛（待预注册，不是已达结果）

| 项目 | 初始目标 | 必须说明 |
|---|---|---|
| 关键语义错误 | 关键回归样本中零已确认新增错误 | 零观察不证明总体风险为零 |
| 人类理解 | 正确率非劣效，成功完成任务耗时目标降低 10% | 要给准确率和时间联合区间 |
| Agent 成功率 | D–A 差异 95% 区间下限高于 -3 个百分点 | 96 任务可能不足以证明，先做功效分析 |
| 按需成本 | C 比 B 的累计输入 Token 目标降低 30% | 不只量 Skill 文件大小 |
| 完整产品 | 报告 D 比 A 的总成本/成功任务；不预先承诺更省 | 一次修订可能抵消压缩收益 |
| 自动触发 | precision ≥95%、recall ≥90% | 观测覆盖、区间和各宿主分别给出 |

若只能改善 style score，不能宣传“提高理解或执行成功率”。若文本质量更好但总成本更高，可以定位为质量模式；若 C 的成本更低且质量非劣，则可以提供经济模式。不要把所有取舍压成单一分数。

## 11. 发布结果所需记录

保存每次 run 的 task/scenario、组别、重复、规则/源码/来源哈希、模型/宿主、profile/语言、触发证据、工作目录初态、原始 usage、各阶段时长、草稿与修订产物、检查报告、语义判定、执行测试和错误原因。公开前移除密钥和个人资料。

生成 task manifest、schema 和协议不代表实验运行。没有真实日志时保留空结果目录，不生成看似真实的演示排行榜。
