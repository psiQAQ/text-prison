# 提示词候选与编辑示例

本页保留可手动采用的提示词和编辑示例，不是模型评测结果或自动执行指令。P0＋P1 已将第 3 节相关原则整合到仓库 Skill 源码；具体范围见[实施记录](../../plans/2026-10-26-readability-evolution.md)。已有事实和权限约束优先；只审阅时不能改原文。

## 1. 适合ChatGPT自定义指令的短版

```text
回答技术问题时，先回答问题，再补必要的解释、依据和限制。
用完整句写清谁对什么做什么。拆开容易误解的名词堆叠，明确有依据的条件、因果和转折；不要为通顺补造关系。
保留专业术语、数字及单位、否定、不确定性、适用范围和引用。代码、公式和原样引文不作风格改写。
允许为了消歧适量增加文字，但不要重复结论、堆砌套话或把所有内容拆成列表。
按我的知识背景解释新概念；不清楚的事实明确说明。不要把最短输出当成目标。
```

这段偏好主要约束面向人的技术表达；不是要让闲聊、创意写作、代码或机器格式都套用同一模板。ChatGPT的[自定义指令](https://help.openai.com/en/articles/8096356-chatgpt-custom-instructions)与[项目指令](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)是可选承载入口；本包不修改账号设置。

## 2. 单次文档改写：把范围说清楚

```text
请改善下面文档的可读性。
读者：已有相关理工知识，但不了解本项目内部实现。
目标：让读者找到结论、理解条件和对象之间的关系，而不是减少专业信息。
范围：只改正文表达；保留标题、代码、公式、数值、单位、标识符、引用与链接目标。
重点处理：有歧义的名词串、指代不清、被省略的关系，以及打断主句的插入说明。
只有来源已经支持的关系才可写明；不得补造原因、步骤、验证结果或前提。
形成改稿后，对照原文核对一次；只做有必要的局部修订。直接给改稿，仅在有无法解决的歧义时简短列出。
```

读者、目标和范围应按实际任务替换；不是每次都让用户填写一张表。已有对话已说明的信息直接沿用。对要求重组目录的任务，可以放宽“保留标题”，但应提醒标题锚点和链接影响；不能默认获得重构全文的权限。

## 3. 已采纳原则与原始候选

**采纳位置：** [主 Skill 的写作与内容保护](../../../skills/text-prison/SKILL.md#写作与内容保护)保留短原则，详细方法集中在现有 [STE-inspired](../../../skills/text-prison/references/ste-inspired.md)。下文保留原始候选措辞，当前运行指导以这两个文件为准，不新建第二份 Skill。

```text
不要以最少字数或Token作为清晰度目标。对有歧义的名词串和被省略的关系，按来源补足对象、动作与联系；允许必要展开，不强制拆句或列表化。遇到这类问题时按需读取STE-inspired参考；原意和保护项优先于文风。
```

主 Skill 已有原意保护和修订次数限制，采纳时只整合必要差量，没有将本页整篇粘入。增补不授权新工具安装、额外模型评审或新的循环。

**按需参考的候选补充：**

```text
当读者必须猜测名词之间的关系时，把有依据的修饰关系展开；固定术语和标识符保留。
当原文已经表达条件、因果或转折但连接不清时，明确该关系；关系未知时报告歧义，不替作者决定。
主语、动作和对象尽量相邻；只移动不改变条件、否定或限定范围的插入信息。
为了理解而重复一个必要名词，通常比换成指代不明的“它”更稳妥。
保留正常的技术主语表达；只改需要读者额外解码、又无表达价值的陌生拟人化或隐喻。
段落需要完整的逻辑联系。步骤可编号、比较可列表或表格，解释和推导不机械碎片化。
```

这些候选内容是对已有消歧规则的增补，不是ASD-STE100的逐条翻译或认证规则。具体方法受前述来源保护约束。

## 4. 在现有五类用途上加少量区别

| 用途 | 可加的一句要求 | 不应增加的限制 |
|---|---|---|
| explanation | 先给当前问题的答案，再解释最关键的机制或证据 | 每次都写长背景；所有回答固定三点 |
| procedure | 在动作前交代已知且必需的适用条件，写清动作对象 | 虚构回滚方案、检查标准或依赖 |
| reference | 说明字段或概念之间的关系，保留定义和机器名称 | 为“自然语言”重命名API或修改默认值 |
| research | 区分观察、解释和推测，保留统计与实验限定 | 删除may/might/could、不显著、误差或限制 |
| agent-spec | 明确执行者、修改范围、条件授权和停止条件 | 将建议写成授权，或用文风规则扩大权限 |

这里沿用[五类用途定义](../../../docs/DESIGN.md#当前职责)，不创造第六种模式。本地 P1 已明确纳入用户指定使用 TextPrison 的技术回答；概念回答通常采用 explanation，科研结论按 research 处理，聊天正文只是交付形式。普通聊天和未指定使用 TextPrison 的技术问答仍不进入此流程。

## 5. 编辑示例：先给上下文，再判断改法

以下全部为本报告构造的**编辑示意**，不是工具输出、模型A/B结果或真实实验数据。它们演示约束如何影响选择，不构成固定字符串替换词典。

### 例一：名词串不能靠猜关系来展开

已知上下文：缓存用于保存模型的推理结果；这里讨论缓存的更新策略。

原句：`模型推理结果缓存更新策略说明如下。`

可改：`下面说明用于保存模型推理结果的缓存采用什么更新策略。`

“缓存”的用途由上下文明确提供。若原文实际上讨论“模型推理时如何更新缓存”，上述改法会改变意思，应先报告两种解释，不能为了读起来顺就选一种。

### 例二：增加连接词，不增加因果

已知上下文：程序先读取配置；只有配置通过校验后才启动服务。

原句：`读取配置，校验通过，启动服务。`

可改：`程序读取配置；只有校验通过后，才启动服务。`

不可改：`程序读取配置，因此服务启动成功。`

错误改法把执行条件变成因果，还把计划动作写成成功结果。连接词越明确，越需要有来源支撑。

### 例三：英文的关系标记可以帮助读者

原句：`The file the script reads contains the settings.`

可改：`The file that the script reads contains the settings.`

增加关系代词，有助于显式标出“脚本读取的文件”。不应把所有英文省略结构都判错，也不应给中文设一条“补that”的机械规则。这里的结构是宾语关系从句。

### 例四：科研描述保留观测边界

原句：`在所测温度范围内，结果提示该补偿方法可能减小漂移，但尚不能排除测量噪声的影响。`

可改：`结果提示：在所测温度范围内，该补偿方法可能减小漂移。但尚不能排除测量噪声的影响。`

不可改：`该补偿方法能减小漂移。`

可改版本只调整组织，保留温度范围、可能性和“尚不能排除”的限定，不换成证据含义可能不同的近义表达。原句已经清楚时也可以不改。

### 例五：不显著不等于相等

原句：`实验未发现两种方法的误差有统计显著差异。`

保留或按背景补足已有比较对象即可。

不可改：`两种方法的误差相同。`

这个例子不需要追求更短的替代句。明确写“不改”，也是合理的编辑决定。

### 例六：无生命主语与被动表达不必消灭

原句：`服务器拒绝了该请求。` 正常技术表达，无需强行改成某个人“拒绝”。

原句：`样品在真空条件下完成测量。` 如果执行者未知或无关，可以保留，不得补出“工程师测量了样品”。

原句：`预算拥抱性能并吞掉等待时间。` 如果文中实际已有成本与延迟数据，应直接说明其关系；没有数据或明确含义时，只能指出这句话表达不清，不能代造结果。

### 例七：格式优化不能触碰机器接口

保留`HTTP_PROXY`、函数名、命令参数、文件路径、数学符号和原样引文。解释这些对象时可以改周围的文字，但不要为了术语一致而重命名它们。列表里的固定字段可以不是完整句，不能把“所有内容必须完整句”应用到JSON或API签名。

## 6. 仅审阅，不自动改写

```text
只审阅这段文字，不修改原文。
指出会影响理解的具体位置，说明读者可能产生的两种解释，或指出缺少哪项必要关系。
已有信息不足以确定改法时，写“需要上下文”，不要给出看似确定的修订。
区分表达问题、事实待核实和纯风格偏好。无需报告无关的规则或给总体分数。
```

审阅输出建议包含“位置—问题—依据—可选处理”，不要求每段都输出固定检查表。轻微文风差异不必升级成错误。

## 7. 提示词本身也要避免的陷阱

不要同时要求“尽可能最短”和“充分解释每个关系”，却不给优先级；建议明确原意和理解优先。不要同时给多套互相重复的文风规则；先排除宿主已有的“所有回答固定列表”“禁止限定词”等冲突默认项。

不要要求展示内部思维链。所谓区分推理与表达，只意味着面向读者的最终文本不能照搬压缩笔记，不意味着另加一个思考模型或公开隐藏推理过程。

不要在没有用到工具的普通回答后附一大段`Not Run`清单。需要工具状态的是明确的工具审阅/交付报告；一般技术问答只保留与用户决策有关的未验证事实。该呈现建议不允许把未运行的检查写成已通过。

不要默认把“更自然”解释为隐藏AI来源、插入错别字或随机改变措辞。这里优化的是理解和用途，不是逃避检测。
