# STE-inspired 跨用途消歧

README、操作说明、API 参考、科研说明、Agent 指令及明确指定使用 TextPrison 的技术回答中，出现术语或关系歧义、名词化隐藏动作、主句被插入信息打断、操作与解释混杂、体裁不合或重复铺垫时读取。先沿用所选用途和语言规则，再处理有依据的表达问题；无需把整篇文档改成一种句式。仅审阅时输出问题和依据，不改原文。

## 通用原则

- **同一概念保持同一名称。** 优先沿用项目术语表、界面名称或已定义的技术术语，不为避免重复轮换同义词。不同对象、状态或步骤确有区别时保留区别；不能凭名称相近就合并概念。
- **让读者知道谁对什么做什么。** 主体影响责任或操作时写清主体；“它”“该项”有多个可能对象时，用已有名称澄清，允许重复必要名词。主体未知或与结论无关时可以保留被动表达，不补造执行者。
- **在读者需要采取动作之前给出必要条件。** 当条件决定动作是否适用时，先交代条件再给动作。保留否定、例外和条件的作用范围，不把所有条件句一律移到句首，也不从结果推造操作前提。
- **区分操作、解释与结果。** 指令说明要执行的动作，解释说明原因或机制，结果说明已有依据支持的观察或预期。不要把“预期成功”改成“已经成功”，也不要把可选操作写成必须执行。
- **按需要组织动作和主题。** 相互独立、有先后关系的动作可以列为步骤；不可分割的操作不机械拆开。段落围绕一个明确主题组织，保留推导、因果和转折所需的联系，不用碎句代替逻辑。
- **用明确表达保留技术含义。** 优先使用能说清动作和对象的词，但保留领域术语、数值、单位和必要精度。前提、检查和失败处理必须有来源；材料不足时指出缺口。模态、权限和证据强度继续受 TextPrison 的内容保护约束，不为风格删除。

## 过度压缩与关系展开

清晰度不取决于字数最少。先指出具体困难：读者是否需要猜对象或关系、跨过插入说明寻找主干，还是在重复铺垫中寻找要点。只处理实际存在的问题；下列结构是审阅线索，不是禁用项，也不用于判定作者是否使用 AI。

- **拆开有歧义的名词串。** 上下文明确修饰关系时，可写成“用于……的……”或完整动作句；固定术语、产品名和标识符保持原样。关系不明时说明可能的解释，不替作者选定一种。
- **补足已有关系。** 条件、并列、转折或因果确有依据时才写明；英语省略关系词造成结构难辨时，可以补回适当的关系词，不强制每处都加 that。不能把先后发生改成因果，把执行条件改成成功结果。缺少依据时指出需要的上下文。
- **让主句易于辨认。** 多层嵌套或连续附加从句隔开主体与动作时，可把非限定性的解释移到邻句，明确各句所指对象。条件、否定和限定的作用范围必须保留；决定讨论对象的限定从句不能随意移走。若移动会改变范围，保留原位置；不为缩短句子拆散推导或段间联系。
- **把隐藏的动作说清。** 名词化使执行者、动作或对象不明时，可按已知事实改成动词表达；执行者未知时不补造主体。领域术语、过程名称以及需要被定义或比较的概念可以保留名词形式，不按后缀或词频批量替换。
- **直接表达机制，保留正常技术搭配。** “服务器返回响应”等表达无需改成人类主语。陌生拟人化或隐喻妨碍理解时，只用材料已给出的机制或关系解释；没有依据就报告含义不清。

## 体裁适配与冗长重复

以解决具体阅读障碍为先，不把妨碍理解的原文风格作为保留目标。无论文本由谁写成，都在授权范围内改善生硬措辞、模板表达和不清楚的结构；事实、技术含义及用户明确指定的语气继续保留。只有风格差异而没有阅读问题时，不因“像 AI”强行改写，也不先鉴定作者身份。

- **按读者任务选择语体。** 操作说明优先说清动作，不用学术式名词化和层叠附加说明掩盖步骤；科研论证保留必要术语、被动、模态和限定，不改成营销式结论或过度口语化。某词或句式在模型文本中更常见，不构成删除理由。
- **按作用处理模板表达与重复。** 在用户允许的范围内，删除没有实质内容的开场、套尾、赞美和反复预告，合并重复结论。先确认它们没有承担必要背景、礼貌要求、消歧、条件限定、有效总结或解释功能。必要推导、失败处理和例子不因篇幅长就删掉，也不设固定压缩率。
- **检查对比和列举是否成立。** 原文凭空制造对立、机械平衡双方观点或为凑数重复列项时，保留有依据的内容，改用准确关系组织。真实对比、实际存在的多方观点和合理列举应保留；不因为用了“不是……而是……”、三项排比或连接词就判错，不补造反方或第三项。
- **把空泛措辞落到已知信息上。** 材料足够时写清主体、动作、对象和依据；不足时指出具体缺口，不虚构例子、来源或机制。“研究表明”等表达应结合紧邻正文、引文、脚注和表格核对，不能因单句没有链接就认定无来源。行业术语有明确含义时不当作空话删除。
- **分别处理整篇与句内问题。** 删除冗余不应把剩余信息塞进更长的名词串；展开关系也不需要增加空泛过渡。沿用现有来源核对，确认新增连接有依据、删减没有丢失限定、移动内容没有改变跨句指代和条件归属，不另加评分或检查轮次。

用户明确选择模板表达的机械诊断时，可按 [Vale 说明](../vale/README.md)选择可选配置；命中只表示字符串出现，不证明该处无用，也不授权扩大改写范围。

## 按用途应用

| 用途 | 适用处理 | 保留的边界 |
|---|---|---|
| README、概念解释、产品帮助 | 统一同一对象的名称，澄清指代，将任务说明与背景分开 | 是否重排由用户所选范围决定，不补写未核实的产品行为 |
| 安装、操作、故障处理 | 说明动作对象、必要条件与已有步骤顺序 | 不虚构前提、验收或恢复策略，不拆散不可分割的操作 |
| API、参数、查询参考 | 核对术语、条件、状态与字段之间的对应 | 不为自然句改动标识符、类型、默认值、表格定义或机器结构 |
| 科研摘要、结果与论证 | 澄清比较对象、代词和适用条件，保留论证联系 | 不删除 may/might/could、误差、否定或限制，不强制主动句 |
| Agent 指令 | 明确执行者、对象、权限条件及停止条件的指向 | 澄清不产生新权限；不得把计划、建议或条件授权写成已获授权 |

## 编辑示例

以下均为**假设上下文中的编辑示例**，不是 CLI 输出或 Agent 实测。上下文给定的事实在真实任务中仍需从材料取得。

前六例依次展示生造短语、主干中断、关系代词省略、名词串、名词动用和陌生拟人化。每例只处理给定上下文中的理解障碍，不把整类结构列为禁用项；英文特有现象不直接转成中文规则。

### 生造短语：说清具体含义

**已知上下文：** 作者用“读者耐心预算”指读者愿意花在背景介绍上的时间。这里的编辑要求是精简背景介绍、保留安装步骤；这个临时说法不是已定义的专业术语或实测指标。

- **润色前：** “请降低这份安装说明对读者耐心预算的消耗。”
- **润色后：** “请精简这份安装说明的背景介绍，保留安装步骤。”

**改动与边界：** 将需要猜测的临时说法展开为已知的编辑对象和动作，不把要求扩大为压缩整篇说明。若材料未解释“耐心预算”的含义，就先指出缺口；不能凭这个词补造读者行为或效果数据。已有明确定义的领域术语即使少见，也不因此替换。

### 嵌套说明：移开解释，保留限定

**已知上下文：** 上文已唯一确定方法 A。使用缓存保存计算过程中的中间结果是它的实现方式；“在所测条件下”和“可能”只限定降低误差的结论。

- **润色前：** “方法 A（它使用的缓存会保存计算过程中产生的中间结果）在所测条件下可能降低误差。”
- **润色后：** “方法 A 使用缓存保存计算过程中的中间结果。在所测条件下，方法 A 可能降低误差。”

**改动与边界：** 将打断主体与动作的附加解释移到邻句，保留缓存用途、实验条件和可能性。若修饰内容用于区分多个方法，就不能照此移走；也不能补成“因为使用缓存，所以降低误差”。这里处理主干中断，不要求所有长句都拆开。

### 关系代词省略（英文）：标清从句边界

**已知上下文：** 脚本读取的那个文件包含设置；这里需要让读者容易辨认“脚本读取的”修饰哪个对象。

- **润色前：** “The file the script reads contains the settings.”
- **润色后：** “The file that the script reads contains the settings.”

**改动与边界：** 补回 that，显式标出宾语关系从句，文件、脚本及读取关系都不变。原句并非语法错误，结构已清楚时可以保留省略；不要求英文每处都加 that，也不给中文设“补 that”或逐个补“的”的规则。

### 名词串：展开已知用途

**已知上下文：** 缓存用于保存模型的推理结果，本段介绍该缓存的更新策略。这串名词不是产品名、标识符或已经约定的完整术语。

- **润色前：** “下面介绍模型推理结果缓存更新策略。”
- **润色后：** “缓存用于保存模型的推理结果。下面介绍该缓存的更新策略。”

**改动与边界：** 先交代缓存保存什么，再说明要介绍的策略，保留“更新策略”这个讨论对象，不补写更新步骤。若材料没有给出缓存用途，就不能排除“模型推理过程中更新缓存”等其他解释。项目已有固定术语时保留其名称，不按连续名词数量拆词。

### 名词动用（英文）：明确动作

**已知上下文：** 评审时间已经确定，此处仅要求将评审安排添加到团队日历。目标读者不熟悉 calendar 作动词的用法，不需要重新选择评审时间。

- **润色前：** “Please calendar the review.”
- **润色后：** “Please add the review to the team calendar.”

**改动与边界：** 将读者不熟悉的名词动用展开为具体动作与目标位置，不改成重新安排时间。这里的 calendar 不因词性转换就被判错；读者熟悉且语义明确时可以保留。项目术语、惯用表达和 API 名称不按词性批量替换。这是英语名词用作动词的例子，与后文“名词化隐藏动作”不同。

### 陌生拟人化：说明实际情况

**已知上下文：** 讨论记录显示，各方反复回到同一个问题，尚未形成新的结论；材料没有说明参与者的动机或情绪。

- **润色前：** “整场讨论正在咬自己的尾巴。”
- **润色后：** “讨论反复回到同一个问题，尚未形成新的结论。”

**改动与边界：** 用已有记录支持的情况替代需要解码的动作隐喻，不补写“参与者拒绝合作”等原因。没有上下文时，应指出比喻含义不清。“服务器返回响应”等正常技术搭配可以保留，不要求把所有无生命主语改成人。

### 关系：保留条件，不补因果

已知程序先读取配置，只有配置通过校验后才启动服务。

- 原文：“读取配置，校验通过，启动服务。”
- 调整：“程序读取配置；只有校验通过后，才启动服务。”

不能改成“因此服务启动成功”。对于上下文不足的“缓存更新，延迟下降”，应指出先后关系和因果关系尚不能确定，不擅自补“因此”。

### 中文操作：澄清对象和条件

假设上下文已说明“它”是刚导出的配置文件，且用编辑器修改该文件。

- 原文：“完成导出后，如果还要修改，可以再打开它。”
- 调整：“导出完成后，如需修改配置，用编辑器打开导出的配置文件。”

这里复用已知对象与操作；若上下文没有说明文件或编辑器，就先指出信息缺口。

### 英文说明：明确指代

假设上下文已确认需要打开的是报告，而非转换器。

- 原文：“After the converter writes the report, open it.”
- 调整：“After the converter writes the report, open the report.”

保留条件与动作，只把代词替换为有依据的名称。无需为了避免重复再换一个报告名称。

### 科研说明：消歧时保留不确定性

假设上下文明确第二句讨论方法 A；以下结果描述仅用于演示。

- 原文：“Under the tested conditions, the results suggest that method A may reduce error. It may also require more memory.”
- 调整：“Under the tested conditions, the results suggest that method A may reduce error. Method A may also require more memory.”

只明确代词所指的方法，保留 tested conditions、suggest、may 与可能的内存代价。不从这句话补造实验数据，也不将可能降低误差改成确定降低。

### 名词化与重复：明确动作，不删前提

假设材料已明确：用户修改配置后必须由用户重新校验，原文后半句只重复这项要求。

- 原文：“配置修改后的再次校验操作执行是必要的，也就是说，完成修改后进行再次校验这一操作是必需的。”
- 调整：“修改配置后，必须重新校验配置。”

调整保留动作、对象、先后条件和必须执行的程度，只去掉名词化外壳与重复。若材料没有明确执行者或强制要求，不能套用此例补出新的用户操作。

### Agent 指令：不扩大条件授权

假设“它”指本次 Git 提交，材料没有表明用户已经批准。

- 原文：“如果用户批准本次提交，检查通过后可执行它。”
- 调整：“如果用户批准本次提交，检查通过后可创建本次提交。”

保留“如果”“检查通过后”和“可”，不能改成直接执行提交的命令。

### 套话与真实对比：分别判断作用

假设这是操作文档，已知必须先保存配置再重启，开场和套尾不承担礼貌或背景要求。

- 原文：“在当今快速发展的时代，配置管理非常重要。保存配置后再重启服务。希望以上内容对你有所帮助。”
- 调整：“保存配置后再重启服务。”

删除不增加信息的铺垫与套尾，保留动作顺序。相反，“这个选项不是删除文件，而是将文件移入归档目录。”明确区分两种行为，只要符合实际行为就应保留；“不是……而是……”不是禁用句式。

### 英文前缀：去掉铺垫，不增强结论

假设表 2 支持所述趋势，前缀没有额外的强调作用，以下只是编辑示例。

- 原文：“It is important to note that the results in Table 2 suggest that method A may reduce error under the tested conditions.”
- 调整：“The results in Table 2 suggest that method A may reduce error under the tested conditions.”

表格依据、suggest、may 和实验条件都保留，不能改成“Method A reduces error.”。同样，“研究表明，在所测条件下方法 A 可能降低误差”若紧接有效引用或已有明确来源，不必因“研究表明”而删改；来源不明时报告缺口，不编造引文。

### 跨句改写：保留条件、数值与关系

假设材料已经明确：在 20–30 °C 的测试中，方法 A 的平均误差比方法 B 低 10%，方法 A 的峰值内存占用也高于方法 B；材料没有给出内存差值或证实两项观测的因果关系，其他温度未测试。以下数值仅用于构造例子，不是研究结果。

- 原文：“在 20–30 °C 的测试中，方法 A 的平均误差比方法 B 低 10%。它的峰值内存占用也更高。其他温度未测试。”
- 调整：“在 20–30 °C 的测试中，方法 A 的平均误差比方法 B 低 10%，峰值内存占用则高于方法 B。其他温度未测试。”
- 不可改：“方法 A 通过增加 10% 的峰值内存占用来降低误差，因此适用于其他温度。”

调整版明确两项观测属于同一测试条件，并消除“它”和“更高”的对象歧义；10% 仍只描述平均误差的相对差异。错误版本改变了数值所指对象，补造因果并把结论推广到未测试的温度。局部更通顺不能抵消这些变化。这里沿用既有来源核对，不增加检查轮次，也不要求其他段落照此合句。

### 可以不改：正常表达与科研限定

“服务器拒绝了该请求。”是正常技术表达，可以保留。“实验未发现两种方法的误差有统计显著差异。”也可以保留，不能改成“两种方法的误差相同”。这两例都不需要为了命中写作规则而生成替代句。

## 来源与适配边界

2026-10-25 读取了 [ASD 官方介绍](https://www.asd-ste100.org/about_STE.html)及 [FAQ](https://www.asd-ste100.org/STE_faq.html)。官方材料说明标准由写作规则与受控词典组成，区分通用词与领域技术词；FAQ 说明部分原则可用于其他写作场景，并指出读者执行步骤前需要知道的条件应先给出。本页从这些方向提炼适合中英文文档的消歧方法，不把英语限制直接翻译成中文要求。

补充参考是社区 [asd-ste100-skill v0.4.0 的固定 Skill](https://github.com/danyuchn/asd-ste100-skill/blob/cd62d297d5ef7cf9f59718cadc233ab2876ea013/SKILL.md)及其[规则摘要](https://github.com/danyuchn/asd-ste100-skill/blob/cd62d297d5ef7cf9f59718cadc233ab2876ea013/references/writing-rules.md)。借鉴其术语一致、结构消歧和保留模态的思路，不采用其中的英语词数、时态、词性或标点硬限制。社区实现不是官方标准；权限与事实保护等约束沿用 TextPrison 自身的规则。

2026-10-26 按下列下载版本全文补充可读性依据；页码从各 PDF 第一页起算。表中研究现象与上面的编辑要求不同：编辑要求是结合 TextPrison 内容保护作出的工程适配，论文没有直接验证这些要求或本 Skill。

| 研究与版本 | 难读现象或机制证据 | 对应处理及证据边界 |
|---|---|---|
| [P00：AI 生成语言研究，arXiv v1](https://arxiv.org/pdf/2610.29162v1)，PDF 1–9、13–20 页 | 部分模型过用名词堆叠、省略关系词和不寻常搭配等结构；受控长度惩罚训练能诱导部分压缩结构 | 展开有依据的关系、避免为短而压缩；语言特征只是加工风险代理，没有直接读者理解实验，不能断言商业模型的训练成因 |
| [P01：语法与修辞风格，arXiv v2 作者稿](https://arxiv.org/pdf/2410.16107v2)，PDF 2–6 页 | 英语续写中的名词化、分词从句及体裁偏移，方向随模型和体裁变化 | 检查隐藏动作、层叠附加说明与体裁适配；不禁用整类结构，不把分布差异当理解困难的因果证明，外置 SI 未包含在已读文件中 |
| [P03：RLHF 长度相关研究，标注 COLM 2024 的 arXiv v2](https://arxiv.org/pdf/2310.03716v2)，PDF 3–8、16 页 | 部分任务的奖励增益明显依赖输出变长，纯长度奖励也可取得较高模拟偏好，另有不随长度增长的任务 | 合并无新增作用的重复，保留必要解释；模拟偏好不是读者理解，论文不支持越短越好或所有 RLHF 都造成冗长 |
| [P06：法律语言加工，Cognition 2022 正式版](https://www.pure.ed.ac.uk/ws/portalfiles/portal/256304933/Poor_Writing_MARTINEZ_DOA17022022_VOR_CC_BY_NC_ND.pdf)，PDF 3–7 页 | 英语短合同的表达调整改善理解与回忆，探索分析中打断主干的嵌套较突出 | 优先检查主干中断；四类修改捆绑，不能独立证明每种改法有效，外置 SI 未取得，不外推为中文技术文档收益 |

另参考 [SALSA 编辑级分析](https://aclanthology.org/2023.emnlp-main.211/)，PDF 5–8 页，提醒一次改写可能同时包含有益编辑和信息错误；局部更流畅不能抵消条件、对象或因果损失。这里不引入其标签体系或自动评分模型。

这些研究不能合并成“所有模型都难读”的结论，也不能据此设句长、词频、依存距离阈值或 AI 词汇黑名单。中文按其表达习惯适配，效果尚未由这些英语研究验证；训练侧的奖励或控制机制不等于提示词能力。上述要求不是新增的 ASD-STE100 标准条款。
