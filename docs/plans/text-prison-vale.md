## 2. 目标、范围与三件套的职责

| 组成 | 负责什么 | 不承担什么 |
|---|---|---|
| `text-prison` Skill | 理解任务、提出适用的优化选项、按用户选择改写、核对原意、解释诊断 | 自动补齐未经来源支持的事实；额外调用评委模型 |
| Vale CLI | 根据明确配置报告词语、术语、链接文字等可机械检查的问题 | 证明语义、科研结论、读者理解或操作一定正确 |
| 按需规则库 | 用短文档保存规则来源、适用条件、例外与内容保护原则；用 Vale 配置选择机器规则 | 全量复制上游标准；把全部品牌风格同时加载 |

产品保留自动发现和显式调用。普通聊天、纯代码修改、逐字转录和纯 JSON 等机器可读输出不进入文风优化。现有 `structured` 路径将在获批实施时退出 Skill 入口；不恢复 JSON Schema 后端。

不维护或执行 Agent 实战、模型评委、A/B 实验、自动触发实验、基准、测试套件、fixtures 或评审网页。本文要求的单次方案审阅是用户指定的文档操作，不能扩展成实战评测。五个子模块仅供只读查阅，不运行其测试。

## 3. Skill 的任务交互

### 3.1 先确定本次工作

读取用户给出的文档、必要上下文和相关项目约定，确定读者、用途、语言、可编辑范围、原文与来源。用途沿用 `explanation`、`procedure`、`reference`、`research`、`agent-spec`；产品帮助由相应用途加 Microsoft 规则处理，不新增第二个 Skill。

只在缺失信息会改变结果或授权时询问。可以从材料判断的普通细节自行处理。自动发现只决定是否提出帮助；审阅请求不自动授权改写，用户原本已明确的修改范围也不因菜单而扩大。

### 3.2 给出适合当前文档的选择

对尚未选定优化方式的请求，提供 2–3 个有实际差别的选项，推荐一个。每个选项用简短文字说明修改范围、所用规则、Vale 调用次数、结构调整程度、用户复核重点和预期改善。不要求用户先理解规则包或配置文件名。

以下是 README 场景的**假设交互示例**，实际菜单应随任务改变：

| 选项 | 修改与规则 | 执行负担 | 预期效果与复核 |
|---|---|---|---|
| 局部清晰化（推荐） | 保留章节和技术内容，使用 Google 技术表达与对应语言规则 | 读取用途、语言和一份品牌摘要；若 Vale 就绪，初检一次，修订后至多复查一次 | 澄清指代、术语和条件；用户重点复核原意和命令上下文 |
| 按读者任务重组 | 先核对前提，再整理安装、最小用例和故障入口；采用同一品牌规则 | 除局部表达外调整结构；Vale 次数不增加，人工需复核章节顺序和链接 | 便于定位操作；可能影响标题锚点，必须同步查引用 |
| 仅检查 | 报告具体问题、位置和建议，不修改原文 | 读取所需规则；Vale 就绪时运行一次，无修订复查 | 提供可处理的问题清单，不保证穷尽语义问题 |

用户已经选定方案、限制“只改术语”或要求直接执行时，简短说明采用的范围后继续，不重复等待选择。选项尚待回复时，不开始依赖该选择的改写。无交互工具时使用简短文字选项，不因工具缺失擅自接受默认项。

### 3.3 执行和交付

按选择加载规则并写作；只读必要的原文与来源。改写后对照原文核对主体、对象、否定、条件、不确定性、数字、单位、因果、版本和引用对应。代码、命令、标识符、公式、原样引文默认保护，除非用户明确要求修改。

来源缺失时，指出具体缺口及其影响，不补造前提、失败策略或验收条件。科研不把 `may`、`might`、`could`、误差范围和适用条件当成冗余删除。

完成初稿后可运行一次 Vale，处理适用诊断并最多进行一次针对性修订、一次 Vale 复查；仅检查模式不修改文档。未解决的实质问题交付给用户，不循环追求零警告或总分。原意核对由当前写作 Agent 完成，不是人工验收或独立语义验证。

最终交付优先给文档或改动入口，并简要列出实质重排、待确认信息及 Vale 状态。不要给每次润色附加大篇审计报告；纯机器格式请求不混入诊断文字。

## 4. 按需规则库

### 4.1 规则选择

| 任务 | 人工写作规则 | Vale 默认配置 |
|---|---|---|
| 英文 README、教程、API、技术解释 | Google + 用途 + 英文；操作章节可加 STE-inspired | `dev-en.ini`，操作文档用 `procedure-en.ini` |
| 英文 UI 文案、产品帮助 | Microsoft + 用途 + 英文 | `product-en.ini` |
| 英文科研说明 | 科研内容保护 + 英文清晰性；只按需要参考品牌原则 | `research-en.ini` |
| 英文 Agent 指令 | 目标、权限、条件、对象和停止条件 | `conservative.ini` |
| 中文文档 | 中文 + 用途；可借用品牌的组织原则 | `zh.ini` |
| 中英混合或多用途文档 | 按章节优化；保持项目既有约定 | `conservative.ini`，不全局套英文风格 |

每个文档默认只选择一个品牌主线。Google 和 Microsoft 的组织原则可以人工按任务借鉴，但不把两个 Vale 包全量叠加。STE-inspired 仅用于适合的操作消歧，不对科研或普通中文施加受控英语词典约束，不声称完整 ASD-STE100 合规。

按需读取上限采用内容范围而非未经测量的 Token 数：通常一份用途、一份语言、至多一份品牌摘要；只有操作说明确有需要时再读取 STE 摘要。核心保护原则留在 SKILL.md，避免每份参考重复。

规则分工参考 [Google Highlights](https://developers.google.com/style/highlights) 与 [Microsoft Top 10 tips](https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice)。这些是写作建议来源，不证明本项目的收益幅度。

## 5. Vale 配置及诊断约定

### 5.1 规则与包

Vale 是唯一机械引擎。配置以相对 `StylesPath = styles` 引用随配置分发的原创规则。英文开发配置声明固定的 [Google v0.7.1 规则包](https://github.com/vale-cli/Google/releases/tag/v0.7.1)，英文产品配置声明固定的 [Microsoft v0.15.1 规则包](https://github.com/vale-cli/Microsoft/releases/tag/v0.15.1)。这是本方案选择的基线，不宣称最新版本。

在相应 `Packages` 字段使用固定发布 ZIP URL：

```ini
Packages = https://github.com/vale-cli/Google/releases/download/v0.7.1/Google.zip
```

Microsoft 使用同样结构的固定地址 `https://github.com/vale-cli/Microsoft/releases/download/v0.15.1/Microsoft.zip`。不在 Skill 运行中下载，也不提交同步得到的第三方包副本。同步步骤只针对用户所选配置，不为中文用户下载两个英文包。

初版采用保守的显式启用列表：`BasedOnStyles` 只包含项目自己的基础规则，按官方支持的 `Style.Rule` 设置启用选定上游规则，避免全量套用后再不断屏蔽。实施时从固定版本核对实际规则文件名、消息和适用语言，在 `vale/README.md` 记录启用列表和理由；不能猜测规则名。具体名单须在实施交付中可见。[Vale BasedOnStyles 与单项规则设置](https://docs.vale.sh/keys/basedonstyles)

原创规则限于具体而稳定的问题，例如“点击这里”类缺乏意义的链接文字，以及由项目明确给定的术语写法；不凭空建立术语词典。中文不加载英文拼写、词数、语态、冠词或大小写规则。科研配置及保守配置不启用“禁用第一人称”“禁用被动语态”“禁用不确定性”或全局极短句要求。无法用少量稳定规则准确表达的建议放在人工参考中。

不同配置的保护要求相同：代码块、行内代码、公式、原样引用不因风格检查而改动。实施时按 Vale Markdown 作用域核对排除项，原样引文需明确配置；链接文字可检查，链接目标不改写。不能把“编辑时保护”误写成 Vale 对所有格式天然完全忽略。[Vale Markdown 格式与作用域](https://docs.vale.sh/formats/markdown)

### 5.2 明确输入、配置和结果

以存在的目标文件为输入；初版支持 Markdown 和纯文本。DOCX、PDF、HTML、MDX 等没有已确认处理方式时，说明不支持，不自动安装转换器或把原件重写成临时格式。混合语言使用保守配置，不实现自动语义分段分类器。

Skill 先核对文件存在、实际安装位置、Vale 可执行程序及所选包是否就绪，再运行参数数组或正确引用的命令。禁止因路径拼错而让 CLI 将输入当作直接文本检查。配置路径用实际绝对路径，目标文件逐个明确传入；不默认扫描整个仓库。

示意命令如下，实际值由用户安装位置和目标文件决定：

```powershell
$skillRoot = 'D:/path/to/project/.agents/skills/text-prison'
$configPath = Join-Path $skillRoot 'vale/dev-en.ini'
$documentPath = 'D:/path/to/project/README.md'
vale --config $configPath --no-global --output=JSON $documentPath
```

`--no-global` 用于避免隐式混合全局配置；返回内容由当前 Agent 阅读，不建立自研检查结果服务。规则选择、显式配置和 CLI 参数以 [Vale CLI 文档](https://docs.vale.sh/topics/cli) 为依据。

若项目已有 `.vale.ini`，先读相关设置。默认保留项目配置；若建议改用本 Skill 配置，在选项中说明差别并让用户选择，绝不覆盖或静默叠加。项目配置的规则不能被误称为 TextPrison 的固定规则集，来自项目的依赖或转换器也不得隐式安装。

| 状况 | 对用户的说明与处理 |
|---|---|
| Vale 不存在或所选包缺失 | `Not Run`，指出缺少项；保留已完成的写作工作，提供手动安装/同步步骤 |
| 配置无效、文件不可读或 CLI 失败 | `Failed`，报告具体错误，不改成“零问题” |
| 运行完成并有提示 | 逐项判断适用性，给出规则名、位置和建议；不把有风格提示等同于全文不可用 |
| 运行完成且没有适用诊断 | 只说明所选规则未发现问题，不宣称语义或理解效果通过 |
| 误报 | 保留原文含义，解释不采纳理由；不为一次误报关闭全局规则 |

局部忽略或词汇表变更会写入文档/配置，只有在用户授权该修改范围时采用，并注明理由。不能为了隐藏警告擅自改变检查范围。

## 6. 安装与日常使用文档

### 6.1 安装责任和主线

本方案只交付仓库文件和可执行的安装介绍。实际安装 Vale、同步上游包、修改其他项目或全局配置需要另行明确授权；Skill 不自动完成这些操作。

安装文档使用 Windows PowerShell 为主线，每步给出前提、工作目录、动作、成功标志及失败处理。macOS/Linux 仅拆分安装 Vale 和 shell 语法确有差异的部分。

1. 用现有 Python 运行项目安装器，把 `skills/text-prison/` 复制到明确存在的目标项目；安装器拒绝覆盖。
2. 通过 [Vale 官方安装说明](https://docs.vale.sh/topics/installation) 安装 CLI；Windows 提供官方包管理器和发布包两种路径，优先介绍 `winget install -e --id errata-ai.Vale`。安装器不会执行此命令。
3. 核对 `vale --version`；这只证明程序能启动，不证明规则正确或集成有效。
4. 选择所需配置，显式运行 `vale sync --config $configPath --no-global` 下载其固定包。中文或保守配置不需要英文包；同步前说明会写入所选 Skill 的 `vale/styles/`。
5. 按文档给出的具体文件路径进行日常调用，理解诊断和未运行状态。此使用示例不在本仓库自动执行成测试。

Codex 使用 `.agents/skills/text-prison/` 和 `$text-prison`；Claude Code 使用 `.claude/skills/text-prison/` 和 `/text-prison`；Pi 保留 `.pi/skills/text-prison/` 和 `/skill:text-prison`。`--agent both` 继续只表示 Codex 与 Claude Code。路径沿用安装器接口，并在交付前静态核对。[Codex Skills](https://learn.chatgpt.com/docs/build-skills)、[Claude Code Skills](https://code.claude.com/docs/en/skills)

自动发现保留，但是否触发由宿主决定；显式调用是文档中的可重复入口。不运行触发实验，也不承诺不同宿主的自动调用一致。

### 6.2 更新、维护及冲突

安装器不覆盖已有 Skill、不安装 Python 包、不创建全局规则或 hooks。更新前读 `install-manifest.json` 并比较本地改动；给用户列出保留与替换范围，未经确认不删除旧目录。不会新增自动更新程序。

固定上游版本更新属于依赖变更，需要说明变化和授权；没有“每次运行同步最新”的步骤。多宿主副本各有自己的配置与包目录，用户按实际使用的宿主维护，文档不宣称它们自动同步。

用户只使用文字指导时无需 Vale；需要机械检查时才承担 CLI 安装和首次包同步。运行负担通常是一次本地检查，修订后最多再检查一次；没有额外模型评委。加载规则和人工核对原意仍会占用时间，不承诺固定 Token 节省比例。

默认不安装 Vale Agent 插件、MCP、编辑 hooks、CI 或 zhlint。官方 [Vale agent-tools](https://github.com/vale-cli/agent-tools/blob/main/README.md) 可作为将来的集成参考，本轮不引入其多 Skill、hook 或额外依赖。

### 6.3 文档内示例

`docs/USAGE.md` 直接包含四类短示例：README 的读者任务组织、中文操作说明的条件与动作、产品帮助的行动文字、科研段落的限定条件保护。示例均标明假设输入、所选方案、预期可观察变化和必须人工核对的内容，不引用未执行的诊断数字，不建立样例文件目录或 fixtures。

## 7. 实施顺序与交付边界（须另获批准）

1. 修改唯一 Skill 和规则索引，完成适用范围、选项交互及来源保护；同步宿主元数据，移除 structured 路径。
2. 加入原创 Vale 规则、六个配置入口和版本说明；核对固定包规则名、适用范围、排除项和命令语义，不同步或运行包。
3. 完成安装、使用、误报和更新文档，确认现有安装器能完整复制所需文件且接口不变。
